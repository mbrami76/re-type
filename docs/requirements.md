# Re:Type – Requirements and assumptions

Status: accepted by the maintainer; updated 2026-11-22. Impact: `critical` (non-negotiable), `major` (less negotiable), `minor` (negotiable). PD = project-defining.

## Requirements

| ID | Requirement | Impact | Type | PD | Verification |
|---|---|---|---|---|---|
| REQ-FUNC-001 | Pressing a global hotkey types the plain-text content of the system clipboard into the foreground window as simulated keystrokes. | critical | functional | yes | unit-tested; verified on Windows 11 in Notepad and Edge |
| REQ-FUNC-002 | The hotkey is user-configurable. The default contains Ctrl and V plus at least one further modifier. | critical | functional | yes | unit-tested; default hotkey registered and fired on Windows 11; changing it in the settings window verified on Windows 10 (old hotkey stops, new one works) |
| REQ-FUNC-003 | When a hotkey is set, the application detects combinations already registered by other applications, reports them, does not use them, and can propose a free alternative. | major | functional | no | to be tested on Windows |
| REQ-FUNC-004 | Retype behaviour is configurable: delay before typing, delay between keystrokes, how newlines are sent, how tabs are sent, trailing-newline removal. Defaults are safe: Enter and Tab in the clipboard text are skipped, never typed; line breaks and tabs written in a template are always typed as Enter and Tab. | major | functional | no | unit-tested; newline, tab and trailing-newline handling verified on Windows 11; timing options not yet varied |
| REQ-FUNC-005 | Typing templates can prepend and append characters and a limited set of text-entry and navigation keys to the clipboard text: Tab, Shift+Tab, Enter, the arrow keys, Home, End, Backspace, Delete; repeat at most 5, wait at most 1000 ms. Shortcuts (Ctrl/Alt/Win combinations), function keys, Esc and every other key are not allowed. A template that breaks the limits is refused on save and switched off (not deleted) on load, with a notice. | major | functional | yes | unit-tested (PRO); to be checked on Windows |
| REQ-FUNC-006 | Each template can be enabled or disabled individually and has its own global hotkey. | major | functional | yes | binding logic unit-tested; registration to be tested on Windows |
| REQ-UX-001 | A system tray icon gives access to the configuration window and to exiting the application. | major | UX/UI | no | to be tested on Windows |
| REQ-UX-002 | Hotkeys can be paused and resumed from the tray menu. | minor | UX/UI | no | to be tested on Windows |
| REQ-UX-003 | Only one instance of the application runs at a time. | minor | UX/UI | no | verified on Windows 10 (message shown, first instance keeps working) |
| REQ-UX-004 | Characters outside the Basic Multilingual Plane (e.g. emoji) are typed correctly, independently of the active keyboard layout. | minor | UX/UI | no | unit-tested; verified on Windows 11 (accents, euro, emoji) in Notepad and Edge |
| REQ-SAFE-001 | Typing in progress can be aborted with Esc, and clipboard content longer than a configurable limit is refused. | major | safety | no | unit-tested with a simulated keyboard; Esc abort and the length limit verified on Windows 10 |
| REQ-DATA-001 | Configuration is persisted as JSON in the user's `%APPDATA%` folder. An unreadable file does not stop the application: it is set aside and defaults are used. | major | data integrity | no | unit-tested |
| REQ-SEC-001 | The application makes no network connections and never writes clipboard content to disk or to the log. | critical | security | no | verified: no networking code or crate (source search, dependency list) |
| REQ-SEC-002 | The application runs without administrator rights by default and never asks for them on its own. Running as administrator is an explicit option chosen by the user (REQ-UX-010). | major | security | no | to be tested on Windows |
| REQ-SEC-003 | Clipboard content is held in memory only while it is being typed. The application keeps no copy of it, and the typing buffer is cleared after every typing run, whether completed, aborted or failed. | major | security | no | unit-tested (wiped after completed, aborted, failed, panicking and refused runs) |
| REQ-SEC-005 | After the clipboard content was typed successfully, the clipboard is emptied. It is not emptied after an aborted, failed or refused run, when nothing was typed from it (image, other formats, ignored files), when the content changed while typing (newer content is kept), or when the user switched the option off. On by default. | major | security | no | unit-tested; verified on Windows 10 (text, option off, Esc abort, clipboard replaced during typing, image, BASIC) |
| REQ-PROC-001 | The application keeps a human-readable log file next to its configuration, with bounded size. | major | process | no | unit-tested |
| REQ-PROC-002 | The application builds with `cargo` into a single self-contained Windows executable with no runtime to install, and uses few third-party crates. | major | process | no | compiles for Windows from Linux; first Windows build to be done |
| REQ-SEC-004 | Released executables are digitally signed (Authenticode, with a trusted timestamp) so Windows and users can verify the publisher and integrity. | major | security | no | not yet verified |
| REQ-PROC-003 | The product is named Re:Type, internal name `re-type`, delivered as one executable with every feature (templates included). A reduced BASIC edition was planned and dropped on 2026-11-22. | major | process | no | both editions compile and pass tests; BASIC verified on Windows 10 (types, single hotkey, settings without Templates) |
| REQ-FUNC-007 | An optional setting converts special characters of the clipboard text into safe characters before typing: off, plain punctuation and spaces (the default; curly quotes, long dashes, ellipsis, special spaces to ASCII; invisible characters removed), or ASCII only (also accents removed, EUR/GBP/JPY, (c), (r), (tm), `?` for the rest). Template text is not converted. | major | functional | no | unit-tested; verified on Windows 10 in Notepad (all three modes) |
| REQ-FUNC-008 | Clipboard content that is not text is handled safely: copied files are typed as paths, as names, or ignored (setting); images and other formats are never typed and the user gets a notice; a clipboard owner that does not answer in time cannot freeze the application. | major | safety | no | unit-tested; verified on Windows 10 with two files, an image, text with image, empty clipboard and a private format; a file copied with Ctrl+C in a real Explorer window also verified (paths and names) |
| REQ-UX-005 | The settings window groups options in tabs, never clips or overlaps texts, resizes with its content and enforces a minimum size. | minor | UX/UI | no | verified on Windows 10 at default, small and large size and after Check and Find free, after switching tabs with the mouse, and with drop-downs opened (three defects found there were fixed); other DPI scales and Windows 11 not tested |
| REQ-UX-006 | The tray menu has a command "Type clipboard now" that types the clipboard into the window the user was working in and, if there was one, the control that had the keyboard focus there (the window and control from before the focus went to the taskbar), with the same options as the hotkey. If that window cannot be brought back to the front, nothing is typed and the user gets a notice. | minor | UX/UI | no | verified on Windows 10 with the command message while the taskbar had the focus: Notepad, and a form with three text boxes (the box that had the focus received the text each time); a click on the real tray menu not yet tested |
| REQ-UX-008 | The tray menu has a command "Pick target and type…" (sniper mode): the user points at the control that should receive the typing and clicks it; the click is not passed on to the program, a frame follows the control under the pointer, Esc or a right click cancels, and the mode ends by itself after 30 seconds. The clipboard is then typed into that control with the same options as the hotkey. Buttons, static texts, the taskbar buttons and menus, and Re:Type's own windows are refused with a notice. The control is given the keyboard focus directly; if it refuses, and for windows that draw their own fields (web pages, WPF, UWP, Qt), the picked point is clicked once to focus it. If neither works, nothing is typed. Only window handles are kept, only for that one run. | minor | UX/UI | no | verified on Windows 10: two Notepad windows (typed into the picked one while the other had the focus), Esc and right click cancel and later normal clicks work, taskbar button refused, a WPF window (click path) and the Windows search box (click path); web browsers and a mouse click on the real tray menu item not tested |
| REQ-UX-007 | The settings window and the tray menu can use a light or a dark colour scheme: follow the Windows app mode (default), always light, or always dark; the choice is a setting and takes effect on Save, and a change of the Windows mode while the window is open is followed. When Windows high contrast is on, its colours are always used. | minor | UX/UI | no | verified on Windows 10 (light, dark, dark tray menu, high contrast switched on and off while the window was open, every tab); message boxes keep the Windows colours (not themable); Windows 11 not tested |
| REQ-ACC-001 | The settings window can be used completely with the keyboard: Tab order follows the reading order, every control has an access key or can be reached with Tab, Ctrl+Tab / Ctrl+PgUp / Ctrl+PgDn switch pages, Esc closes the window, focus marks and access-key underlines are always shown. | major | UX/UI | no | verified on Windows 10 with synthetic keystrokes (Tab order, Alt+key on labels and buttons, Ctrl+Tab, Esc) |
| REQ-ACC-002 | Every control exposes its role, name, state and value to assistive technology through the standard Windows accessibility interfaces: standard controls only, each field named by the label before it, buttons with unambiguous names, explanatory and status texts reachable as read-only text fields, tab control and pages named. | major | UX/UI | no | verified on Windows 10 by reading the MSAA tree (edit, button, check box, combo box, tab list and tabs, access keys and values correct); NVDA 2026.3.1 run on Windows 10: window title, tab pages, field names, roles, access keys, check box state and combo box value are spoken correctly; JAWS and Narrator not tried |
| REQ-ACC-003 | Results shown after an action (hotkey check, find free, save) are announced to assistive technology without moving the focus, and are also readable as text. | minor | UX/UI | no | NVDA did not speak a change of an unfocused text; fixed by moving the focus to the result while a screen reader is running (SPI_GETSCREENREADER); NVDA then speaks the check result and "Saved and applied."; other screen readers not tried |
| REQ-ACC-004 | The windows follow the Windows high-contrast colours and the system font and DPI. | major | UX/UI | no | high contrast verified on Windows 10 (switched on and off with the window open); other DPI scales not tested |
| REQ-ACC-005 | The tray icon can be used without a mouse: the menu opens with the menu key or Shift+F10 on the icon, Enter on the icon opens the settings, and the menu items have access keys. | major | UX/UI | no | menu opened at the icon position (version 4 tray messages) and its access keys shown on Windows 10; Enter on the icon not yet tested with a real keyboard |
| REQ-UX-009 | An option on the Startup page starts Re:Type when the user signs in to Windows (per-user, no administrator rights needed). The entry is removed when the option is switched off, repaired when the program was moved, and the page says when Windows itself has the entry disabled in Task Manager. | minor | functional | yes | verified on Windows 10 (registry); real sign-in not tested |
| REQ-UX-010 | An option on the Startup page makes Re:Type run as administrator: when it is started without administrator rights it asks Windows for them (UAC consent prompt) and restarts itself elevated; if the user declines, it keeps running normally and shows a notice. There is no silent elevated start (no scheduled task with highest privileges), so every elevation needs the user's consent. The window and tray tooltip show when it runs elevated. The tray menu also has a command *Restart as administrator*, shown only while Re:Type runs without these rights: it restarts Re:Type elevated for that run only, saves nothing, and keeps running as before if the user declines. | major | functional | yes | option verified on Windows 10 incl. the UAC prompt (accept, decline) and at sign-in on Windows 11; tray command: to be tested on Windows |
| REQ-UX-011 | "Pick target and type" (REQ-UX-008) can be switched off in the settings (default on): when off, the tray command is hidden and has no effect. It can have its own optional global shortcut (default none) that starts the same one-shot mode; the shortcut is checked like every other hotkey (valid, free, different from all other hotkeys) and is registered only while the mode is on. | minor | functional | yes | unit-tested (config); to be verified on Windows |
| REQ-DOC-001 | A Help page in the settings window (also opened by F1 and by the tray command Help) explains every option, every mode (hotkey, Type clipboard now, Pick target and type) and every limit, with warnings for the risky ones (administrator rights, clipboard history, passwords, start at sign-in). It is plain text in a read-only field: keyboard- and screen-reader-accessible, themed like the window. | major | functional | yes | unit-tested (content); verified on Windows 10 |
| REQ-DOC-002 | An About page in the settings window shows the product name, edition and version, the copyright holder (Michele Brami), the website and the source code address, the GPL notice (version 3 or any later version, no warranty, where the full text is) and the third-party components. Two buttons open the website and the source page in the browser; the addresses are fixed in the program. | major | functional | yes | unit-tested (content); to be verified on Windows |
| REQ-LIC-001 | The program is free software under the GNU General Public License, version 3 or (at your option) any later version. The distribution contains the full licence text (LICENSE), a third-party notices file, and every source file carries the copyright and SPDX licence line. All third-party components are compatible with the GPL. | major | legal | yes | checked by a test over the sources |
| REQ-UX-012 | The settings window shows the settings file as a button named `settings.json` (file name only, no path); activating it opens the folder that contains the file with the file selected. | minor | functional | yes | to be verified on Windows |
| REQ-UX-013 | The settings window has two panes instead of tabs: a list of the option groups on the left and the details of the selected group on the right. Keyboard, screen reader and dark mode keep working (REQ-ACC-001..005, REQ-UX-007). | major | functional | yes | to be verified on Windows |
| REQ-I18N-001 | The interface is available in English, Italian, French, German, Spanish and Portuguese. The language follows Windows by default and can be chosen in the settings. Log files and the settings file keys stay in English. | major | functional | yes | catalog completeness checked by a test; to be verified on Windows |
| REQ-I18N-002 | Users can add or replace a translation by putting a language file in the `lang` folder next to the settings file. A language file is plain data and can never run code or change what the program does: it is read as JSON with fixed size limits, only text for known English strings is taken, text is only ever shown, never executed, used as a format, a path or a command, and entries that carry control or direction-changing characters or that drop the `{...}` tokens or `{0}` placeholders of the English text are ignored. A broken file is ignored with a notice and English is used. | major | security | yes | unit-tested |
| REQ-I18N-003 | Right-to-left text (Hebrew, Arabic) is typed in the order of the clipboard text, character by character, unchanged in every special-character mode except ASCII only (which replaces it by ?). The left-to-right and right-to-left marks are kept; embeddings, overrides and isolates and other invisible characters are removed in the default mode. The settings window is not mirrored for right-to-left languages. | major | functional | yes | verified on Windows 11 with a Hebrew and Arabic text; mirroring not supported |
| REQ-PROC-004 | The program is portable: one executable, no installer, nothing needs to be installed or registered. If a file named `portable` or a `settings.json` lies next to the executable, the settings, the log and the `lang` folder are kept in that folder; otherwise in `%APPDATA%\re-type`. The optional start-at-sign-in entry is the only thing written outside that folder, and only when the user switches it on. | major | process | yes | unit-tested (folder choice); to be tested on Windows |
| REQ-UX-014 | Shortcut fields show which parts of the text are not recognised: an unknown key or modifier name is underlined in red while the user types. | major | UX/UI | yes | planned |
| REQ-UX-015 | Next to each shortcut field a "Listen" button records a combination of modifier keys plus one other key pressed by the user and writes it into the field; the field can still be edited by hand. While listening, Re:Type's own hotkeys do not react. | major | UX/UI | yes | planned |
| REQ-UX-016 | Recognised modifier and key names in a shortcut field are shown as small "keys" (chips); unrecognised text stays plain text. | minor | UX/UI | no | planned, depends on the field control chosen |
| REQ-UX-017 | A button on the Hotkeys page helps with shortcuts that are already taken (meaning to be confirmed with the owner of the request). | major | UX/UI | no | open question |
| REQ-COMP-002 | Linux builds for the KDE and GNOME desktop environments, running from the desktop tray, with the same behaviour as on Windows. Windows is delivered first; Linux scope and schedule are decided later. | major | compatibility | no | deferred |
| REQ-COMP-001 | Target: Windows 10 and 11, 64-bit. Implemented in Rust (stable toolchain); no Python or other runtime. | major | compatibility | no | compiles for x86_64-pc-windows-gnu; to be tested on Windows |

## Assumptions

| ID | Assumption | Linked REQ | Status |
|---|---|---|---|
| ASM-001 | `SendInput` with Unicode key events is accepted by common target applications (Notepad, browsers, Office, Windows Terminal). Known exceptions: windows running elevated (blocked by UIPI unless the application is elevated too), some games and remote-desktop clients that read scan codes. | REQ-FUNC-001, REQ-SEC-002, REQ-UX-004 | partly verified on Windows 11: Notepad and Edge accept Unicode SendInput; elevated windows, games and remote clients not tested |
| ASM-002 | `RegisterHotKey` fails with error 1409 when another application already registered the same combination. It **cannot** detect shortcuts that applications handle internally (e.g. Ctrl+Shift+V in a browser) or via low-level keyboard hooks. | REQ-FUNC-003 | verified from Windows API documentation; the limit affects the wording of REQ-FUNC-003 |
| ASM-003 | Modifiers still held from the hotkey would combine with the typed keys; waiting until they are released (with a timeout) avoids this. | REQ-FUNC-001 | verified on Windows 11 with the hotkey sent as keyboard scancodes (no stray menus seen); a real keyboard and slower holds not yet tested |
| ASM-004 | Superseded (Python-specific). | – | withdrawn |
| ASM-005 | Superseded (Python-specific). | – | withdrawn |
| ASM-006 | The default Ctrl+Alt+Shift+V does not clash with typing: on the Italian layout Ctrl+Alt acts as AltGr, and AltGr+Shift+V produces no character. | REQ-FUNC-002 | open |
| ASM-007 | In Rust the typing buffer can be a buffer the application owns, wiped with volatile writes, so REQ-SEC-003 can be met for the application's own memory. The clipboard memory itself belongs to Windows and is only read. | REQ-SEC-003 | verified by unit tests |
| ASM-008 | A code-signing certificate or signing service is available to the maintainer. Interim: a self-made certificate, trusted only on own machines; SmartScreen warns elsewhere. Since the project is free software, programmes for open-source projects are options. | REQ-SEC-004 | open |
| ASM-009 | A native Win32 interface (tray icon, settings window) written with the `windows-sys` crate is sufficient; no GUI framework is needed. | REQ-UX-001, REQ-PROC-002 | accepted at design; look and feel to be judged on Windows |
| ASM-010 | Wayland has no universal way for an application to register a global hotkey or inject keystrokes. Expected routes: the XDG GlobalShortcuts and RemoteDesktop portals (KDE, GNOME), or libei; X11 sessions allow both directly. Support differs by desktop version. | REQ-COMP-002 | open, research when Linux work starts |
| ASM-011 | GNOME shows no tray icons by default; it needs the AppIndicator extension. KDE shows them natively through StatusNotifierItem. | REQ-COMP-002, REQ-UX-001 | open, research when Linux work starts |

| ASM-012 | Another application can hold the clipboard in delayed rendering and never answer, so reading it must have a time limit (4 s) on a separate thread. | REQ-FUNC-008 | implemented; the timeout path itself not provoked on Windows |
| ASM-013 | When the clipboard holds both text and an image (or files), CF_UNICODETEXT is preferred; otherwise CF_HDROP; images (DIB, DIBV5, bitmap, PNG) and unknown formats are not typed. | REQ-FUNC-008 | verified on Windows 10 with synthetic clipboard objects |
| ASM-014 | Emptying the clipboard removes it from the live clipboard only. Windows clipboard history (Win+V), cloud clipboard sync and clipboard managers may already hold a copy that Re:Type cannot remove. | REQ-SEC-005 | documented in README; not tested |
| ASM-015 | After a tray click the taskbar is the foreground window, so the window to type in must be remembered (WinEvent foreground hook, handle only) and Windows must let Re:Type bring it back (input-queue attach). Windows may still refuse in some situations; then nothing is typed. | REQ-UX-006 | verified on Windows 10 for Notepad |

| ASM-016 | Dark menus and dark control themes rely on uxtheme functions that Windows does not document (ordinals 104, 133, 135, 136) and on the theme names `DarkMode_Explorer` and `DarkMode_CFD`. They exist from Windows 10 build 18362 (1903); they are looked up at run time and skipped when absent, so an older build shows the light colours and nothing breaks. A future Windows version could change them. | REQ-UX-007 | verified on Windows 10 LTSC 2021 (build 19044); Windows 11 not tested |
| ASM-017 | Standard Win32 controls give screen readers what they need (role, name from the label before the control, state, value). Windows draws check box text in black in the dark theme, so check boxes and the tab strip are painted by the application while remaining real controls. NVDA behaves well with this window (tested); JAWS and Narrator are assumed to. | REQ-ACC-001..005 | MSAA tree and NVDA verified on Windows 10; JAWS and Narrator not tried |

| ASM-018 | A low-level mouse hook can swallow the click that picks the target, `WindowFromPoint` ignores a layered click-through frame window, and `Esc` can be taken with a temporary `RegisterHotKey`. Windows that draw their own content (browsers, WPF, UWP, Qt) offer no child window per field, so the only generic way to focus a field there is a click at its position. A click can press a button if the user picked one, so buttons and static texts are refused. | REQ-UX-008 | verified on Windows 10 with Notepad, WPF and the search box; Chrome and Edge not tested |
| ASM-019 | `ShellExecute` with the verb `runas` shows the UAC consent prompt on the secure desktop and starts the elevated copy; declining returns an error and nothing starts. A per-user `Run` registry value starts a program at sign-in; Task Manager's Startup tab disables it through `StartupApproved\Run`, not by deleting it. An elevated start at sign-in therefore shows a UAC prompt each time. | REQ-UX-009, REQ-UX-010 | verified on Windows 10 |

## Editions

There is one edition. The Windows-specific parts (hotkeys, keystroke injection, clipboard, tray) sit behind one platform interface so that Linux can be added later.
